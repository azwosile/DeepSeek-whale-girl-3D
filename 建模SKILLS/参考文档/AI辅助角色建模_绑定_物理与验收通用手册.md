文章展示的链路可以概括为：

```text
明确角色设定 → 图像生成与选择 → 按精度需求拆分部件
→ 三维生成/重建 → DCC Bridge 导入 Blender
→ 多轮装配纠错 → 骨架与测试姿势 → 布料/头发动态 → 输出与记录
```

值得借鉴的不是某一段“万能提示词”，而是以下原则：

- **生成不是终点。** 后续装配、对齐、权重和碰撞修复往往占据大量时间。
- **拆件是资源分配策略。** 面部、手、饰品等高敏感区域，应获得更高精度和独立控制；不是越碎越好。
- **优先复用可用资产。** 有可靠身体、头部、骨架或材质时，不要为了方便脚本而全部重建。
- **约束必须反复传递。** 保留脸、UV、材质、骨架和部件可选性，比一句“做得更好看”有用。
- **以姿势暴露权重问题。** 转头、抬臂、屈肘、屈膝应在复杂动力学之前检查。
- **可控动画与物理模拟可以混合，但必须说明。** 发束骨骼的主动动画，不等于原生被动头发物理。

需要补充的工程限制：

1. 漂亮的 GIF、四张姿势图或“文件已保存”，不足以证明整段无穿模。
2. 文章中的案例路径、参数和资产结构，不能直接照搬到另一角色。
3. 展示了布料和头发动态，不等于完成自碰撞、亚帧、手指接触、引擎运行或任意新动作验收。
4. 本会话主要处理已经生成的资产，并未重新实践文章中每一个生成阶段。

## 2. 最重要的工程结论

1. **先保护正确的东西，再修错误的东西。** 脸、已确认的比例、UV、材质和源资产，都应有明确的保护范围。
2. **先修初始状态，再加动力学。** 初始衣物或发束已经互相穿透时，盲目增加质量步数、刚度或碰撞厚度通常不能解决根因。
3. **代理稳定不代表渲染网格安全。** 最终要检查实际参与显示的高分辨率基础表面。
4. **对象间零交叉不等于自碰撞通过。** 头发—身体、裙子—身体通过，头发内部、裙褶内部、指间仍可能相交。
5. **顶点在外部不等于三角面没穿过物体。** 检测必须覆盖面和边的穿越。
6. **整数帧通过不等于亚帧通过。** 缓存线性插值与骨架、衣物的非线性插值可能在帧间产生新的接触。
7. **空间指标与时间指标要同时约束。** 不能只把形状修好，再指望后处理平滑解决所有跳动。
8. **求解数组通过不等于最终缓存通过。** 坐标变换、浮点精度和修改器顺序会改变实际结果。
9. **保留位置不等于保留语义。** 顶点没变，不代表材质、权重、动作、驱动器或修改器行为没变。
10. **阈值是验收合同，不是躲避失败的工具。** 失败后临时放宽标准、裁掉难测区域、忽略失败帧，都不是真修复。
11. **最大值、分位数和局部曲线都要看。** 最大值不变时，更多点也可能变差；全局改善时，某个局部也可能恶化。
12. **有限范围通过要说清范围。** 可以交付有用的阶段预览，但不能把它说成完整物理资产。

## 3. 先定义交付物与验收合同

### 3.1 先回答这些问题

- 目标是静态展示、Blender 动画、引擎角色、实时虚拟形象，还是可编辑制作源？
- 交付需要 `.blend`、GLB、FBX、缓存、贴图，还是仅视频？
- 骨骼动画、布料模拟、骨骼次级运动、烘焙后校正分别允许到什么程度？
- 要验证哪些动作、帧率、持续时间和运动幅度？
- 哪些部位不可改？哪些允许改权重？哪些允许改拓扑？
- 正常附着、衣物叠层和装饰性穿插是否允许？谁批准、如何记录？
- 性能目标、骨骼数量、影响数、面数和贴图预算是什么？

### 3.2 区分四种交付等级

| 等级 | 可以声称 | 不能顺带声称 |
|---|---|---|
| 静态造型通过 | 指定视角和静态姿势符合要求 | 动作、物理、引擎运行通过 |
| 绑定测试通过 | 已测姿势中权重和关节表现可用 | 任意动作、精确抓握通过 |
| 有限动作缓存通过 | 指定动作与采样范围的缓存通过约定检查 | 原生实时物理、未测动作通过 |
| 约定范围的完整物理验收 | 验收矩阵中所有必测项通过，例外透明且经确认 | 数学上永不碰撞或任意场景普遍正确 |

“完整”必须有边界。一个经过充分测试的有限动画，可以完成其**约定范围**验收；它仍不是任意动作的通用保证。

### 3.3 不可变与可变清单

建议在任务开始时保存：

```yaml
protected:
  face_geometry: true
  expressions: true
  approved_clothing_design: true
  original_uv_layout: true
  source_files: true
allowed_changes:
  hair_secondary_rig: true

  corrective_cache: true
  topology_changes: require_separate_review
acceptance:
  runtime: Blender

  sample_policy: integer_and_subframe
  exceptions: named_and_reviewed_only
```

这只是模板。不要把它机械套用到需要重新拓扑或写实布料的项目。

## 4. 输入资产审计与参考图优先级

### 4.1 建立资产清单

每个输入至少记录：来源、文件哈希、对象数、材质数、贴图路径、单位、轴向、包围盒、是否带骨架、是否带动画、是否存在重复身体或备用部件。

生成式三维资产常见的问题：

- 同一包里混有身体、备用身体、袜腿、内衬和重复饰品。
- 衣服与素体来自不同生成结果，比例并不一致。
- 贴图中画了链条，而模型里又有一条真实链条。
- 看起来连续的面实际上是相互重叠的独立薄片。
- 手指在图像上分开，但内部拓扑或关节附近已相交。

先确认“哪些部件应该使用”，再开始绑定。重复叠穿会把简单装配变成无法稳定求解的多层接触问题。

### 4.2 参考优先级

建议明确排序：

1. 用户明确要求保留的现有资产和原始设计图；
2. 用户确认过的版本或风格；
3. 同一角色的补充视图；
4. 流程文章与通用范例；
5. Agent 自己补充的合理猜测。

不能用漂亮的教程角色替代用户角色，也不能因为示例头模更容易绑定，就换掉已经认可的脸。

### 4.3 看图要产出检查表

至少记录正面、背面、两侧、头部、肩颈、腰部、裙摆、手、脚和饰品的：轮廓、相对位置、可见接缝、色区、遮挡关系、不可见区域假设。

单张图不能唯一确定深度。若没有背面参考，必须区分“设计已有证据”和“为了完成模型而作的假设”。

## 5. 坐标、尺度、对齐与变换

### 5.1 一开始统一单位

碰撞距离、布料厚度、骨骼长度、重力响应和缓存误差都依赖尺度。先确认角色高度和世界单位，再设置毫米级间隙。

不要把一个角色上有效的绝对高度切线复制到另一个角色。更通用的分区方式是：

- 相对角色高度的比例；
- 到骨骼、发根或腰线的距离；
- 拓扑连通区域；
- 语义顶点组；
- 人工确认的材质或结构边界。

### 5.2 优先用可逆整体变换完成粗对齐

初期用父级空物体统一缩放、旋转和平移，比逐点修改所有对象更容易回退。随后再做局部贴合。

应用变换前后要检查：骨架是否共享相同变换、法线和负尺度是否正确、缓存处于局部还是世界坐标、导出器是否再次转换轴向。

### 5.3 验收不是只看包围盒

包围盒正确不代表头、肩、肘、腰、膝的位置正确。建议同时使用解剖或结构标记点：颈根、肩峰、肘、腕、髋、膝、踝、裙腰、裙摆。

坐标方向一旦误判，前后投射可能命中手臂、背面衣物甚至另一条腿，产生远大于真实需求的修正。

## 6. 拆件与装配：不要把修复变成重新设计

### 6.1 连通分量只是起点

用边连通性识别独立部件很有效，但“第几个连通分量”不是稳定语义。重新导出或重新拓扑后，编号可能变化。

应把分量识别结果写成清单，并结合材质、包围盒、原图和渲染确认其用途。需要长期引用时，保存来源对象、语义名称和哈希，不只保存一个整数下标。

### 6.2 最小上游原因原则

先找导致问题的最小上游原因：

- 全部衣服偏移：先查整体变换。
- 只有袖口穿模：先查局部权重和袖口截面。
- 转头才拉长：先查发根约束与父子关系。
- 只有渲染变黑：先查材质、灯光、烘焙和贴图绑定，不先改几何。
- 只在跳帧后异常：先查求值和缓存状态，不先增加物理阻尼。

### 6.3 用户接受设计，不等于所有几何问题都已解决

“领口设计保留”意味着不能擅自重新设计领口；它不自动证明领口附近碰撞合格。反过来，碰撞修复也不能成为改变用户已确认风格的借口。

几何修复若涉及明显轮廓或结构变化，应单独列出影响，而不是混在一次“物理优化”里悄悄完成。

## 7. 衣物贴合、层级与遮罩

### 7.1 建立正确的层级关系

常见顺序是身体、贴身内层、衬衫、外衣、裙摆或饰件。具体顺序由设计决定，不能只按对象名称推断。

对每一层记录：内侧参考表面、允许厚度、应贴合区域、应保留褶皱区域、接触区域和不应投射的部件。

### 7.2 投射碰撞体要按语义限制

沿径向修裙摆时，低垂手臂可能挡在射线上。若使用整个身体作为投射目标，算法会把裙子推到手臂外面。

正确做法是：

1. 用骨盆、大腿等相关区域计算候选修正；
2. 再使用完整身体和完整相关衣物进行最终碰撞检查；
3. 不把“局部投射体”误当成“最终验收范围”。

### 7.3 开放表面不能只用最近法线判断内外

封闭、法线一致的单层实体可以提供较可靠的有符号方向。衬衫、背心、裙褶、飘带往往是开放或多层表面，最近法线可能指向错误的一侧。

应结合：前后语义、连通区域、上一帧接触侧、射线、局部面片和完整三角形检测。最近距离可作为信息，不应独自决定大幅推移方向。

### 7.4 遮罩不是通用的防穿模方法

允许的情况：明确隐藏设计中始终被覆盖的内层区域，并保留可撤销记录。

不允许伪装成修复的情况：为了得到零碰撞或好看截图，隐藏本应存在的身体、衣物、失败区域或坏帧。

遮罩使用后还要检查：新的边界是否露出、动作后是否失去覆盖、导出副本是否正确应用、物理报告是否写明排除范围。

### 7.5 不要破坏贴图与几何的对应关系

若贴图中已有链条、缝线或装饰印记，移动真实装饰而不处理相应贴图，可能产生“双影”。先判断是几何重复、贴图绘制还是正常装饰，不要靠偏移几何制造新的错位。

---

## 8. 拓扑、UV、法线与材质保护

### 8.1 建立保护哈希，但不要迷信单一哈希

可以分别记录：

- 顶点坐标与顶点数量；
- 面顶点顺序、边、三角化方式；
- UV 层及逐角 UV；
- 面材质索引；
- 形态键；
- 骨权重、骨骼静止矩阵；
- 对象变换、父级、修改器顺序；
- 动作、驱动器和关键帧。

只比较顶点坐标不能证明材质和动作没变；只比较拓扑不能证明权重没变。

### 8.2 形状修改与拓扑修改分开管理

保持顶点数和顺序的校正，容易写成逐点缓存。重新拓扑、合并顶点、应用会改变数量的修改器，则会破坏缓存索引对应。

如果必须改变拓扑，应建立新的拓扑版本，并重新生成权重、语义分区、缓存和所有依赖顶点编号的报告。不能继续套用旧 MDD。

### 8.3 检查退化面、重复面与接缝

至少检查零面积面、极短边、非流形连接、重复面、翻转法线、UV 缝处分裂的重合顶点和内部重叠表面。

注意：为了保持 UV 而存在的分裂顶点，不应直接无差别焊接。检测可以建立临时的几何邻接关系，但修改源拓扑必须另行验证 UV、硬边、材质边界和权重。

### 8.4 法线修复也可能改变外观

统一法线方向有助于碰撞，但不能对带硬边、风格化法线或倒置描边壳的模型做无差别重算法线。基础表面、描边壳和特殊着色层应分开处理。

---

## 9. 基础绑定与动作测试

### 9.1 优先复用有效骨架

先确认骨架层级、静止姿态、轴向、骨骼命名、现有权重和约束。新建一套骨架并不是默认答案。

身体、头部与头发应有明确的一致驱动关系，避免身体转了而头或发根留在原处。控制骨、变形骨和遗留次级骨最好放在不同集合中。

### 9.2 权重最低检查项

```text
未赋权顶点数 = 0（对需要变形的区域）
非有限权重数 = 0
权重和 ≈ 1（在明确数值容差内）
每顶点影响数符合目标平台限制
不应影响该部位的骨骼权重 = 0
```

四影响是常见交换或引擎预算，不是 Blender 对所有模型的绝对要求。不要为了满足某个默认数字，盲目丢掉必要的变形影响。

### 9.3 姿势测试应先于复杂物理

建议从基准姿势开始，分别测试：左右转头、抬臂、屈肘、前臂旋转、屈膝、抬腿、下蹲、髋部转动，再做组合动作。

检查关节塌陷、拉丝、扭转、衣物与身体的相对运动、发根分离和脚部漂移。每组动作应有返回基准姿势的阶段，便于分辨累计状态与单次姿势问题。

### 9.4 QA 动作不是表演动画

一组关节测试动作不能称为生产走路。生产走路还涉及步幅、重心、脚锁定、地面接触、身体起伏和节奏。脚 IK、手部接触和面部动画也应分别验收。

## 10. 手指、头发与裙摆的精细绑定

### 10.1 手指

建议分别建立每指关节链，并提供弯曲、张开及拇指对掌控制。左右手坐标符号、局部旋转轴和拇指运动平面不能简单照搬。

验证至少分为四层：

1. 控制属性能否驱动骨骼；
2. 权重是否正确带动皮肤；
3. 指间、指尖与掌心是否自交；
4. 接触物体时是否穿透、滑移或悬空。

**前两层通过，不代表抓握完成。**

抓握测试应使用明确尺寸的球、圆柱或盒体，测试开合过程而不只看最后一帧。若需要精确接触，可考虑约束、IK、接触限位和校正形态；这些只是候选技术，必须重新验证，不能作为本次已完成能力来写。

### 10.2 发根与发束

建议分成附着区、过渡区、主体摆动区和末端区。根部固定不能只靠一个世界高度阈值，因为倾斜发束、转头和身高变化会使该阈值失效。

过渡区应同时考虑：到根部的拓扑距离、骨骼影响、发束连通性和与身体的原始接触。

若一条边的一端被硬锁，另一端被避碰推开，即使两个点都“有合理权重”，仍可能出现严重拉伸。正确排查顺序是：定位边和帧 → 查看两端权重与可动掩码 → 检查保护原因 → 再决定是否调整范围。

不要把扩大可动掩码说成已经改好了原始发根绑定；这可能只是后校正自由度的调整。

### 10.3 裙摆

腰部应有清晰的固定或柔性过渡区域。径向骨骼链可用于轻量次级运动，但不能自动代表真实褶皱或厚度。

环状代理需要正确的初始半径、腰线、裙长和腿部空间。骨盆或大腿椭球过小，会出现代理稳定但高分辨率裙子被腿穿过的问题。

饰品、链条、内衬和主裙面应区分。将所有细节统一当成同一张布，容易使饰件变软、褶皱自交或引入不合理约束。

## 11. 物理表示与初始状态

### 11.1 先选表示，再调参数

| 表示 | 优点 | 主要风险 |
|---|---|---|
| 直接高分辨率 Cloth | 接近最终表面 | 计算量大，对初始自交和细小面很敏感 |
| 低分辨率布料代理 | 易于稳定与调试 | 代理与最终表面可能脱节 |
| 骨骼弹簧/次级链 | 可控、轻量、适合风格化 | 不自带完整表面碰撞保证 |
| 代理驱动骨骼 | 能保存可编辑骨架动作 | 拟合误差、依赖循环、缩放异常 |
| 烘焙后网格校正 | 易复现，可直接检查最终面 | 只适用已烘焙动作；不是原生耦合物理 |

### 11.2 初始状态四关

1. **静止无碰撞基准：** 观察无碰撞、无外力时是否自行爆炸或剧烈漂移。
2. **固定端基准：** 检查 pin 组、固定权重和初始绑定偏移。
3. **接触基准：** 分别启用身体、衣物、自碰撞，定位哪个接触体系引发异常。
4. **最终网格基准：** 检查模拟开始前的高分辨率表面，不能只看代理。

若禁用碰撞时稳定、启用碰撞后剧烈震荡，应优先检查初始嵌入、碰撞方向、固定点与碰撞体冲突，而不是只增加阻尼。

### 11.3 碰撞体拓扑必须稳定

动态变形后再做可能改变拓扑或面片对应的简化，会给接触跟踪带来风险。优先使用固定拓扑碰撞体，或明确验证简化策略的稳定性。

低模胶囊或椭球可以提升稳定性，但必须覆盖真实身体的运动范围；不能因为代理间隙足够，就推断真实膝盖、大腿或肩膀不会穿出。

### 11.4 初始自交是独立阻塞项

本次扩展检查在未应用骨架与缓存的原始网格中也发现了真实交叉。这说明“调好求解器”并不能替代静止网格修复。

正确顺序通常应是：部件语义分类 → 排除重复或错误内层 → 恢复合理静止间距 → 保留或重建 UV/权重映射 → 小规模模拟 → 完整动作检查。

这不意味着可以擅自删除内部面；先判断它们是否属于内衬、厚度、设计结构或备用部件。

## 12. 碰撞检测的完整性

### 12.1 检查实际求值后的网格

通常应检查经过骨架、缓存和相关变形修改器后的基础表面，而不是只检查编辑模式中的静止网格。

```python
# 示意：实际项目须明确修改器可见性和坐标约定。
dg = bpy.context.evaluated_depsgraph_get()
eo = obj.evaluated_get(dg)
mesh = eo.to_mesh()
try:
    mesh.calc_loop_triangles()
    # 读取顶点、三角形，并统一到同一坐标空间。
finally:
    eo.to_mesh_clear()
```

同时核对 viewport 与 render 的修改器级别是否一致。否则“检测网格”和“渲染网格”不是同一个对象。

### 12.2 可动区、边界区、固定区分开统计

至少区分：

- 三个顶点都可动的面；
- 仅部分顶点可动的衔接面；
- 全部固定的面；
- 已核实并登记的附着例外。

只检查全可动面，会漏掉跨越掩码边界的三角形。某些持续领口交叉正是藏在这类边界中。

### 12.3 三角面对数不是视觉破洞数

一个可见问题可能产生很多相交面对；多个小问题也可能只产生少量面对。计数要用于定位和回归，不应直接写成“有几千个破洞”。

至少保存：帧号、对象对、三角形索引、顶点索引、所在区域、交叉类型和代表性坐标。

### 12.4 碰撞修正不要在共享顶点处简单累加

多个相邻面可能给同一个顶点重复提出相似修正。简单求和会放大位移，导致过度鼓起和跳变。

可以考虑最大必要修正、带权平均、局部约束求解或有上限的合成更新。无论采用哪一种，都要重新检查面级碰撞，不能只看顶点距离。

### 12.5 描边壳独立处理

倒置 Solidify 描边常常不是物理表面。基础物理检测可以排除它，但必须明说，并单独审阅它是否产生可见黑边穿出或异常。

“排除描边壳”不是允许忽略任何难以修复的可见表面。

## 13. 自碰撞：本次最重要的补课

### 13.1 为什么对象间检查不够

裙子作为一个对象可以不穿身体，同时裙褶互穿；头发可以避开背心，同时不同发束互穿；手部可以位于身体外侧，同时指尖进入掌心。

完整矩阵必须显式包含：头发内部、裙摆内部、指间、手指—掌心，以及需要模拟的饰件内部关系。

### 13.2 不能把 BVH 候选计数直接当最终结论

先处理共享顶点邻接、重复面对、退化三角形、几何接缝、共面候选和普通相切。

本次采用的一项进一步复核是：

1. 排除共享索引顶点的邻接候选；
2. 计算两个三角形相对于对方平面的有符号距离；
3. 要求双方均超过容差地跨越对方平面；
4. 计算三角形与对方平面的截线区间；
5. 区间有超过容差的重叠，才计为明确的非共面交叉。

共面候选不能因此自动通过，仍需二维投影相交、重复面及层叠语义检查。

**交线段长度不是穿透深度。** 很浅角度的交叉可以产生很长的交线；报告必须正确命名指标。

### 13.3 静止已有问题也要报告

可以把交叉分成：静止已有、动作新增、原有交叉扩大、只在某种求值路径出现。

“第 1 帧就有”不是豁免理由。它可能表明源模型已有结构问题，也可能是有意的造型层叠，必须逐项分类。

### 13.4 正常附着例外的最低要求

一项合法例外应有：明确区域、用途、涉及对象或面片、为何不是可见穿出、允许动作范围、批准依据和复查方式。

不能写成“原来的交叉都不算”。发根附着例外也不能扩展成发束之间任意互穿的许可证。

### 13.5 检查器自身也要验证

建议建立小型夹具：完全分离的三角形、仅共享顶点、仅共享边、真正穿越、近共面、完全重复和极小退化面。

只有发现明确反例时，才可以据此否决通过；仅仅没有报告交叉，还不足以证明检查器覆盖了所有情况。

## 14. 空间修形与时间连续性必须一起求解

### 14.1 三类不同问题

- **穿模：** 不同表面不应穿越。
- **形状破坏：** 发束或布料边长、局部面积、轮廓发生过大变化。
- **时间跳动：** 相邻帧出现异常位移或速度变化。

它们不能只靠一个指标衡量。

### 14.2 常用指标及单位

对顶点位置 `x[t, i]`：

```text
帧间位移：d[t,i] = ||x[t+1,i] - x[t,i]||
位置二阶差分：a[t,i] = ||x[t+1,i] - 2*x[t,i] + x[t-1,i]||
边长偏差：e[t,(i,j)] = | ||x[t,i]-x[t,j]|| - L_ref[t,(i,j)] |
边长比：r = L_current / L_ref
```

位置二阶差分本身仍是长度单位；在时间步一致、定义清楚时，除以 `Δt²` 才可作为离散加速度近似。帧间位移也包含角色主动运动，不等于纯抖动。

极短参考边会放大比值，因此应同时报告绝对偏差、参考边长度和相对比值，不能只看一个巨大比例。

### 14.3 为什么独立逐帧修形后再平滑容易失败

每帧的最近面、接触侧或可行区域可能不同。逐帧投射会选择不同分支；后补平滑把点平均进碰撞体，再次投射又把点推到另一边。

常见结果是：边长指标改善，最大帧间位移却大幅恶化；或者画面大部分平滑，只在个别帧突然弹跳。

### 14.4 更可靠的联合更新思路

```text
生成空间修形提议
→ 对提议本身施加时间正则与边界衰减
→ 检查完整候选轨迹的时间限制
→ 检查受影响的实际三角面接触
→ 检查迭代更新路径的穿越
→ 接受，或对整个局部轨迹一致回退
```

关键点是**接受每次更新之前**已经考虑时间条件，而不是结束后才平滑。

但这仍不自动解决自碰撞：如果约束列表里没有头发内部、裙摆内部和手部接触，算法不会神奇地替你保证这些项目。

### 14.5 回退应保持时间一致

只回退某一帧，可能把原本小的空间问题变成大的时间跳变。对一个顶点在整个窗口中的更新使用一致缩放，是一种更可控的策略。

全序列统一的微量退让也可能帮助避开数值边界，但需要重新验证：非凸碰撞体外部的两个安全状态，其线性插值不一定仍然安全。

### 14.6 最大值不能替代分布

至少检查最大值、p95/p99、超过阈值的数量、最差帧、最差顶点和局部曲线。

若全局峰值不变，但 p99 增大，报告应写“最坏跳动受限，但更多点的变化可能增大”，不能写成“动画全面更平滑”。

## 15. 局部窗口、边界与残差追踪

### 15.1 局部窗口的作用

短窗口便于控制内存、定位问题和进行有界测试。固定窗口两端的若干帧，可避免直接破坏与外部轨迹的衔接。

窗口长度、固定帧数和衰减宽度都不是通用常数，应根据帧率、运动频率、发束长度和接触变化速度确定。

### 15.2 边界会成为新的瓶颈

当窗口中部改善后，最大残差可能转移到固定边界或衰减区域。这并不一定意味着根部需要解锁，也不一定意味着刚度不足。

先绘制整段逐帧残差曲线，再检查：热点是否落在窗口边界、两个窗口间是否有遗漏、当前峰值是否只是未覆盖区域。

### 15.3 自适应选窗口，但必须有停止条件

可按当前最大残差选择新窗口，并设置最多窗口数、迭代数、计算预算和最低改善要求。每次都重新计算全段指标，防止“修一个点，另一个地方恶化”。

反复移动窗口直到数字变好，不等于修完物理。若新证据表明主要问题是自交或无效静止形态，应改变工作阶段，而不是继续追逐同一个峰值。

### 15.4 不要扰动原本稳定的发束

用既有失真区域、连通关系和语义约束缩小自由范围。曾经允许某个区域移动，不代表每次都必须优化它。

对未改区域做一致性检查，有助于防止无关发束被“顺便平滑”而丢掉原设计。

---

## 16. 缓存、数值精度与重新打开验证

### 16.1 明确坐标与修改器顺序

世界坐标与局部坐标不能混用。若缓存以局部坐标写出，应使用正确的对象逆变换，并验证实际读回结果。

常见顺序示意：

```text
原始网格 → 骨架变形 → 限定区域缓存覆盖 → 非物理描边/显示层
```

这不是所有项目的唯一顺序，但任何顺序都必须被记录和验证。对身体加头发的合并网格，缓存应有明确影响组，避免冻结脸、手指或身体动画。

### 16.2 写完缓存后至少做三次不同性质的检查

1. 写出前：求解数组的形状、接触和时间指标。
2. 写出后：逐帧检查缓存映射误差、顶点数和保护区。
3. 独立重开：从保存的 `.blend` 和实际 MDD 重新求值，重新检测碰撞与运动。

第三步不可由第一步替代。

### 16.3 小到肉眼看不见的误差，也可能翻转接触判断

贴着碰撞边界的候选，可能因逆变换、float32 存储、矩阵运算顺序或插值产生新的交叉。

本次曾出现：求解数组通过，保存后的两个整数帧却失败。后来通过很小且全轨迹一致的退让，再对实际缓存复核，解决了那一类边界问题。

经验不是“固定退让某个百分比就一定安全”，而是：**保留数值裕量，并在最终表示上验证。**

### 16.4 Float64 内部迭代与 Float32 最终输出

重叠窗口之间保留较高精度，能减少反复量化；最终仍需按实际缓存格式测试。容差应事前定义，不应为了让某次结果通过而临时改大。

### 16.5 缓存是交付的一部分

交付清单应包含缓存目录、相对路径、帧率、帧范围、时间映射方式、文件大小和哈希。

复制 `.blend` 却漏掉 MDD，不是有效交付。修改动作、权重、对象变换或拓扑后，旧缓存的验收结果通常失效。

## 17. 亚帧、连续碰撞与压力测试

### 17.1 为什么整数帧安全，帧间仍会相交

缓存点可能线性插值，而碰撞体的骨架、旋转或关键帧曲线按另一条路径运动。两端安全不能保证中间安全。

本次对已通过全部整数帧检查的缓存补测四分之一帧，确实检出了新的头发—背心交叉。这是验收范围扩展后得到的反例，不应被忽略。

### 17.2 分清三种不同结论

| 方法 | 可以支持的结论 |
|---|---|
| 每帧整数采样 | 已检查的整数帧通过 |
| 1/4、1/8 等亚帧采样 | 已采样的亚帧通过 |
| 有适用假设和误差边界的 CCD | 在指定运动模型和容差下，区间连续检测通过 |

增加采样密度不自动成为数学上的连续无碰撞证明。求解迭代内部的顶点扫掠，也不等于动画帧之间完整的三角形连续碰撞检测。

### 17.3 压力测试设计

基础动作通过后，再增加：快速转头与反向、躯干扭转、左右迈步、较深蹲起、手臂贴身、头发扫过肩颈与裙摆、手指张合与抓握。

参数应写清：角度、速度、持续时间、缓入缓出、是否存在瞬间跳变、是否需要物理预热。

不要用物理上无限加速度的瞬移去要求普通求解器保持自然，也不能把合理的快速变向全部排除掉。

### 17.4 初始状态失败时，不应跳到新动作认证

若未变形源网格就存在未分类自交，先完成结构修复与例外清单，再继续压力动作。否则测试只会生成更多报告，却没有可靠的物理初始条件。

## 18. 二次元渲染与材质兼容性

### 18.1 先锁定用户认可的风格

硬分层阴影和柔和插画式 Toon 是不同方向。应在相同姿势、相近机位和受控灯光下比较，再确认偏好。

风格试验尽量只改材质和渲染设置，并验证网格、UV、权重、骨架和动作未被顺带改变。

### 18.2 原贴图会限制最终画风

贴图里已经画入的褶皱、渐变和高光，不会因为加了 ColorRamp 就消失。不要把带绘制光影的底色当成纯反照率。

强行提高全局高光，容易让深色制服、皮肤或脸显得塑料化。优先对语义区域分别控制，而不是一套参数套全身。

### 18.3 Shader to RGB 的边界

Blender 的 Shader to RGB 用于 EEVEE 风格化着色；它不是可直接随 GLB/FBX 搬到任意引擎的标准 PBR 表达。

渲染工程可以使用复杂 Toon、描边和特效；交换工程则需要目标平台可实现的材质方案。两个分支应明确分开。

### 18.4 不同工具不要混称

- **Paper朱辅助工具：** 本次曾检查并试用部分材质/描边相关函数，不代表插件全部功能和 UI 已通过当前 Blender 版本测试。
- **Goo Engine：** 自定义 Blender 构建，不是往任意新版 Blender 装一个普通插件就自动获得全部功能。
- **lilToon：** Unity 侧的 Toon 方案，不是 Blender 原生插件。
- **Komikaze：** 商品宣传中的版本支持范围，不等于其全部效果在当前工程逐项验证完成。

演示图属于其他模型和作者，不能当作自己的角色已经达到该效果的证据。

### 18.5 多帧检查着色稳定性

单帧好看仍可能在转头时出现阴影跳带、法线闪烁、描边变粗、透明排序或镜面噪声。物理验收和着色时序验收相关，但应分别记录。

## 19. 导出与回读

### 19.1 编辑源与交换资产分开

保留高质量编辑工程；在临时副本或专门分支中做贴图简化、遮罩应用、材质转换、骨骼清理和导出。

不要为了导出方便直接破坏原始高分辨率贴图、复杂材质和可编辑控制器。

### 19.2 黑图烘焙要实际检查像素

“烘焙操作成功”不代表贴图有有效颜色。需要检查尺寸、最小最大值、均值、非黑像素比例，并实际查看图像。

缩放或复制图像后，也要检查打包数据是否仍引用旧图，材质是否绑定到了正确的新图像。

### 19.3 导出后重新导入

至少验证：对象数、骨骼数、角色高度、轴向、材质、贴图、动画帧范围、顶点是否随骨骼移动、是否出现非有限坐标。

FBX 回读可能存在帧偏移；比较时应对齐时间，而不是把导入器的一帧偏移误认为动画全部损坏。

导入器生成的骨骼显示辅助对象，不应混进角色包围盒、面数或模型数量统计。

### 19.4 引擎验收必须在目标引擎里做

Blender 或回读成功不能替代 Humanoid 映射、重定向、实时物理、性能、LOD、移动端限制或引擎 Toon 材质测试。

目标已明确为 Blender 烘焙动画时，也不应擅自把引擎移植当成本轮必交付物。

## 20. 自动化执行、MCP 与断线恢复

### 20.1 不根据宿主操作系统猜终端

Windows 主机上的桥接终端可能是 Bash。先确认实际 shell、当前目录和路径规则，再执行命令。

### 20.2 长任务采用启动与查询分离

```text
短超时启动 Blender → 保存 command_id
→ 按返回偏移读取新增日志 → 获取最终退出状态
→ 读取结构化报告 → 核对输出文件与哈希
```

长任务超时可能只是请求返回，并不表示计算已结束。不要在结果未知时重复启动同一写入操作。

对于命令行 Python 脚本，显式配置脚本异常的非零退出码，避免“脚本断言失败但进程仍按默认方式退出”造成误判。

### 20.3 错误、失败与完成都是终态

轮询程序不能只识别 `completed`，还要处理 `failed`、`cancelled` 等状态，否则会永远轮询已经失败的命令。

### 20.4 会话失效与任务失效分开处理

连接会话过期时，应按正常协议重新初始化，不绕过鉴权。旧命令或任务卡可能同时失效，也可能仅因注册表回收而不可查询。

恢复后先查输出文件、报告和现有进程，再决定是否重跑。源文件和命令标识都应有本地记录。

### 20.5 文件读取不是原始字节的同义词

文本读取工具可能增加行号、规范化换行或分块截断。需要校验哈希时，应去除工具附加信息、恢复正确换行，并确认所有分块来自同一版本。

媒体转移应验证文件长度和 SHA-256。传输完成后再检查视频能否完整解码，不能只凭文件扩展名认定有效。

### 20.6 不泄露连接凭据

报告、截图、总结文档和可下载工程中，不应包含桥接地址中的秘密令牌、授权头或连接配置。诊断网络错误时也不要把含凭据的完整异常原样发布。

## 21. 版本、证据与失败归档

### 21.1 版本号不是质量等级

最新文件可能是失败试验。建议同时维护：最后可用基线、当前候选、失败试验和验收范围。

```text
source/             原始资产与参考
accepted/           已通过明确范围的版本
experiments/        有记录但未通过的候选
reports/            数值、范围、环境、哈希
previews/           对照图和动画
scripts/            可复现操作
```

目录形式可以调整，关键是状态明确、依赖清楚、不能覆盖原始文件。

### 21.2 每次报告应回答六个问题

1. 从哪个版本开始？
2. 实际改了哪些数据？
3. 哪些数据必须且确实没改？
4. 检查了哪些对象、帧、采样和指标？
5. 哪些失败或未验证？
6. 哪个文件才是这次可用产物？

### 21.3 失败样本是资产

保留导致爆炸、跳变、黑图、缓存边界交叉和自交的最小测试条件。它们可以成为回归测试，避免另一个 Agent 或下一轮会话重新走一遍错误路线。

不要因为候选失败就只留一句“效果不好”；保存失败帧、对象对、指标、输入版本和拒绝原因。

### 21.4 审阅证据的等级

```text
文件存在 < 文件可打开 < 数值检查
< 独立重开复核 + 实际图像审阅
< 完整约定动作/采样/交付环境的验收矩阵
```

完整视频解码只证明媒体结构和帧数，不代表已经人工连续观看。抽样审阅应列明帧号和视角。

## 22. 完整验收矩阵

下表是一份建议基线，应按项目删改并事先确认。不是说本次已经全部通过。

| 类别 | 最低检查 | 合格证据 | 常见假通过 |
|---|---|---|---|
| 源资产 | 几何、材质、UV、权重、动作清单 | 哈希与结构报告 | 只说“看起来没变” |
| 静止状态 | 物体间接触、自交、固定端 | 面级报告与多视图 | 只检查代理 |
| 骨架权重 | 未赋权、归一化、影响数、极限姿势 | 权重报告与姿势图 | 自动权重无报错 |
| 发根/腰线 | 固定区、过渡区、附着例外 | 区域清单与运动测试 | 用高度切线一刀切 |
| 对象间碰撞 | 身体、衣物、头发、裙摆完整关系 | 实际求值网格全段报告 | 只测几个关键帧 |
| 自碰撞 | 发束、裙褶、指间、指掌 | 窄相复核及结构分类 | 把静止已有全部过滤 |
| 时间连续性 | 峰值、分位数、局部曲线 | 全序列指标 | 只看平均值 |
| 亚帧 | 指定亚帧采样或适用 CCD | 采样范围与失败列表 | 把整数帧结果推广到区间 |
| 缓存 | 映射、坐标、索引、路径、重开 | 独立进程复核 | 写出函数返回成功 |
| 动作覆盖 | 标准动作与压力动作 | 明确参数及结果 | 测站姿就说所有动作安全 |
| 手部接触 | 张合、对掌、抓握过程 | 指掌/物体接触检查 | 控制器能动就算抓握 |
| 渲染 | 正背侧、近景、描边与着色时序 | 实际渲染和审阅记录 | 好看的一张图 |
| 导出 | 指定格式、回读、目标环境 | 回读/运行报告 | 扩展名正确 |
| 可复现性 | 顺序播放、跳帧、重开、相同输入 | 差异报告 | 仅一次偶然通过 |
| 交付 | 场景、缓存、贴图、说明、限制 | 清单与哈希 | 只交 `.blend` 漏缓存 |

发布条件应类似：

```python
accepted = (
    source_contract_passed
    and rest_state_passed
    and inter_object_contacts_passed
    and required_self_contacts_passed
    and temporal_metrics_passed
    and subframe_policy_passed
    and required_action_suite_passed
    and reopened_cache_passed
    and required_visual_review_completed
    and artifacts_verified
    and every_exception_is_explicitly_reviewed
)
```

不能把 `accepted` 简化成“脚本没崩溃”或“某个碰撞计数为零”。

### 23.3 通用时间指标

```python
import numpy as np

# positions: (time, vertices, 3)，坐标空间和时间步须一致。
def motion_metrics(positions):
    x = np.asarray(positions, dtype=np.float64)
    assert np.isfinite(x).all()
    step = np.linalg.norm(np.diff(x, axis=0), axis=2)
    second = np.linalg.norm(np.diff(x, n=2, axis=0), axis=2)
    return {
        "max_step": float(step.max()),
        "p99_step": float(np.quantile(step, 0.99)),
        "max_second_difference": float(second.max()),
        "p99_second_difference": float(np.quantile(second, 0.99)),
    }
```

这段代码只算指标，不是物理求解器，也不单独决定是否有抖动。

### 23.4 安全的验收控制流

```text
读取基线与输入哈希
→ 检查静止结构和保护条件
→ 运行小范围候选
→ 检查空间、接触、自碰撞、时间指标
→ 若失败：保存报告，不升级交付状态
→ 若通过：生成版本化缓存
→ 独立重开并全范围复查
→ 渲染和实际审阅
→ 验证交付文件
→ 最后更新任务状态与交付清单
```

### 23.5 不变性检查示例

```python
assert same_vertex_count
assert same_topology_version
assert protected_face_error <= agreed_tolerance
assert original_material_assignment_preserved
assert original_uv_contract_preserved
assert no_unexpected_weight_changes
assert baseline_files_not_overwritten
```

当任务本身要求重建拓扑时，应改为“新旧对应与转移质量检查”，而不是保留一个不可能成立的拓扑相等断言。

## 24. 常见症状的排查顺序

| 症状 | 优先排查 | 不应立即做的事 |
|---|---|---|
| 一启用碰撞就爆炸 | 初始穿透、固定点、碰撞厚度、尺度 | 盲目增加质量步数 |
| 代理正常但衣物穿腿 | 代理覆盖、拟合误差、真实表面 | 只展示代理截图 |
| 发根拉成长条 | 两端自由度、硬切线、接触侧 | 解锁整片头发或改脸 |
| 大部分帧平滑，个别帧弹跳 | 接触分支切换、逐帧回退、插值 | 只看均值或强行模糊 |
| 修形后更抖 | 是否真正联合了时间约束 | 继续无限后补平滑 |
| 整数帧零交叉，运动模糊穿模 | 亚帧与不同插值路径 | 宣称渲染器随机出错 |
| 数组通过、缓存失败 | 坐标、浮点、索引、修改器顺序 | 放宽碰撞范围过滤 |
| 自交计数很大 | 邻接、共面、重复面、真交叉分类 | 当作几千个独立破洞 |
| 背面出现肤色或开口状区域 | 射线命中、材质/UV、遮挡、拓扑 | 未诊断就归因于物理 |
| 导出贴图全黑 | 有效像素、烘焙通道、目标图像 | 仅检查文件存在 |
| 回读尺寸巨大 | 单位、轴向、辅助对象、重复变换 | 再手动缩放全部骨骼 |
| 新动作突然失效 | 是否使用旧缓存、原验收覆盖 | 宣称已验证动作之外也安全 |
| 断线后不知道是否完成 | 命令状态、报告、文件哈希 | 直接重跑整套写入脚本 |

## 25. 给建模 Agent 的任务模板

### 25.1 装配任务

> 以指定身体和头部为唯一基准，先检查所有输入、坐标和连通部件。保留脸、表情、原 UV 和已确认材质；不要导入替代头模。逐件装配，保留源文件和备用件。每次只修复最大的已确认问题，输出同机位前后对照及结构报告。保存新版本，不覆盖基线。

### 25.2 绑定任务

> 优先复用有效骨架。明确控制骨和变形骨，验证归一化、未赋权顶点和平台影响数。先制作转头、抬臂、屈肘、屈膝与下蹲测试；只在有证据的区域修改权重。动作和材质保持可追溯，不把 QA 动作说成生产走路。

### 25.3 物理任务

> 先验证初始高分辨率表面、固定端和自交。分别建立身体/衣物/头发/裙摆/手部的接触矩阵，再选择代理或直接模拟。每个候选同时检查形状、对象间碰撞、自碰撞和时间指标。缓存保存后独立重开，检查整数帧与约定亚帧，渲染并实际审阅。未通过的项目明确保留，不通过过滤失败区域获取零计数。

### 25.4 风格渲染任务

> 在独立材质分支中比较硬阴影与插画式 Toon，保持相同姿势和受控机位。不要修改脸部几何或用新贴图覆盖原始纹理。说明 Shader to RGB、描边及目标引擎兼容性。检查转动时的着色稳定性，而不仅是静帧。

### 25.5 交付任务

> 列出最后可用基线、当前候选、通过范围和未验证项。提供场景、缓存、贴图、预览、数值报告、文件哈希和使用说明。若未完成完整验收，标题和首段必须明确，不将实验文件包装成最终资产。

## 26. 从本次工程重新安排一遍顺序

如果重新开始一个相似项目，建议采用以下顺序，避免在后期才发现基础结构不适合物理：

1. 确认交付目标、参考优先级和不可变条件。
2. 审计输入资产，排除重复身体、重复装饰和错误叠层。
3. 统一坐标、尺度与解剖标记点，完成可逆装配。
4. 在原始静止网格上检查对象间交叉、内部自交、退化面和法线。
5. 分类真实附着、装饰层叠与必须修复的几何问题，建立例外清单。
6. 修复静止结构并验证 UV、材质、轮廓；必要时建立新拓扑版本。
7. 做基础绑定和明确的关节 QA 动作。
8. 做手指、发根、腰部过渡的专门检查。
9. 用小规模静态和慢速动作验证物理表示、碰撞体与固定端。
10. 将对象间碰撞、自碰撞、形状保持和时间连续性一起纳入候选评价。
11. 运行完整动作，再运行快速变向等压力测试。
12. 保存缓存，独立重开，检查整数帧、亚帧和实际求值运动。
13. 在已锁定几何与动作上完善 Toon、描边和镜头表现。
14. 分别完成 Blender 交付与目标交换格式/引擎的验收。
15. 归档失败用例，发布有边界、可复现的结论。

**最大的顺序修正：把静止自交和初始碰撞状态提前，而不是等到很多轮避碰、修形和渲染之后才补查。**

## 27. 附录：实证结果、失败路线与当前阻塞

以下数字用于说明经验来自哪些实际结果，不是其他角色的推荐参数。

### 27.1 早期装配、绑定与渲染

- 现有身体加头发被用作基准，服装按连通部件拆分；备用身体、腿部和饰品没有重复叠穿。
- 基础绑定阶段保留了原网格、UV 和面材质索引；建立约六秒的关节测试动作，检查指定衣物/身体关系。
- 初期 GLB/FBX 导出曾出现全黑底色烘焙，失败文件明确标为拒绝使用；后续版本重新生成贴图并回读验证。
- 硬阴影 Toon 与柔和插画式 Toon 在独立场景中比较；最终选择插画式方向。该选择不代表物理质量自动通过。
- 精细绑定增加了手指控制、头发链和裙摆链；驱动器和归一化权重通过，不代表精确手部接触完成。

### 27.2 主要失败路线

| 路线 | 观察到的问题 | 可迁移教训 |
|---|---|---|
| 高分辨率/多层接触直接启动 Cloth | 出现大幅位移或爆炸 | 先修初始接触，检查尺度与固定端 |
| 只提高密度、刚度和质量步数 | 仍不稳定 | 参数不能替代正确初始条件 |
| 稳定的低模裙摆代理 | 高分辨率裙子仍被大腿穿过 | 最终表面必须独立检测 |
| 全身体射线包络修裙摆 | 命中低垂手臂，裙摆被错误外推 | 投射体按语义限制，验收体仍完整 |
| 共享顶点累加所有面修正 | 位移被放大 | 使用有界合成或联合约束 |
| 大幅抬高头发可动高度线 | 接触和外观恶化 | 不要用全局阈值替代过渡区诊断 |
| 独立逐帧修形后平滑 | 形状改善但出现约厘米级跳变 | 时间条件应进入接受更新之前 |
| 按整个连通发束回退 | 可能一个分量都无法接受 | 问题不一定能靠事后筛选消除 |
| 求解数组零交叉后直接导出 | 保存缓存后出现失败帧 | 必须独立重开检查最终表示 |
| 只测整数帧和对象间碰撞 | 漏掉亚帧与大量内部自交 | 验收矩阵必须提前完整 |

### 27.3 已完成的有限范围改进

| 阶段 | 头发最大边长偏差 | 最大帧间位移/二阶差分概况 | 结论 |
|---|---:|---|---|
| v050 | 40.11 mm | 约 9.23 / 2.55 mm | 当时的有限范围基线 |
| v055 | 23.80 mm | 约 25.00 / 24.99 mm | 形状改善、时间严重恶化，拒绝 |
| v057 | 25.56 mm | 约 22.75 / 22.93 mm | 再次拒绝 |
| v063 | 25.43 mm | 实际缓存峰值约保持，部分 p99 略增 | 有限动作/整数帧范围改进 |
| v066 | 19.35 mm | 实际缓存峰值约保持，本轮 p99 略降 | 进一步有限范围改进 |

v066 的局部目标网格最大边长偏差：第 47 帧约 25.43→8.47 mm，第 72 帧约 22.60→8.34 mm，第 83 帧约 21.31→15.16 mm。剩余整段峰值在第 38 帧。

这些结果证明联合约束和补足窗口覆盖是有效的局部方法，**并不证明自碰撞或亚帧已经通过**。

### 27.4 扩展验收发现的反例

对 v066 的额外检查得到：

- 720 个四分之一帧样本中，5 个样本失败：61.25、61.5、89.25、89.5、89.75；涉及头发—背心，最大 8 个三角面对。
- 11 个姿势样本的窄相复核中，头发最多确认 3,632 个非邻接非共面交叉对，裙摆 2,341 对；左右手分别最多 51、49 对。
- 头发中涉及可动范围的明确交叉对，样本最大为 3,175。
- 在原始网格静止坐标、尚未应用骨架或 MDD 时，就确认了头发 1,115 对、裙摆 1,487 对、左手 13 对、右手 2 对明确交叉。
- 共面候选仍单独保留，未自动判为正常，也未把面对数当成可见缺陷数量。

这些是不同检测定义与范围下的数字，不能把 BVH 候选数和窄相确认数混在一起比较。窄相使用约 1 微米的平面/交线容差；它不是“毫米级穿透深度”的测量。

独立的手部求值复现检查比较了顺序播放、跳帧和切换缓存显示后的跳帧，在所测帧上手部位置差为零。因此没有证据把自交问题归咎于跳帧不一致。

### 27.5 当前不能签署完整验收的原因

1. 初始网格自交尚未完成语义分类和修复。
2. 运动中的头发、裙摆和手部自交尚未修复并通过全段复验。
3. 原始 v066 仍有上述亚帧失败；后续内部候选只能按其实际复核结果另记，不能倒推原版本通过。
4. 发根附着例外尚未逐项完成审查，不能把历史固定接触整批视作已批准。
5. 新动作压力测试和精确抓握尚未完成全流程验收。
6. 亚帧离散采样本身不等于区间连续碰撞证明。

因此，**最后交付的 v066 仍是明确限定范围的预览，不是完整物理通过版本。** 新增诊断没有修改其源网格、脸、衣装设计或骨权重，也没有把检查失败的版本升级为最终交付。

### 27.6 后续修复应从哪里开始

- 先对静止头发和裙摆的主要连通部件进行内部交叉分类，区分重复面、生成式残留、衣物厚度、饰件与真实相交。
- 对必须修复的源网格作局部解缠或必要的结构修复，同时保护外轮廓、UV 和材质；不能只把所有交叉点径向推开。
- 重新建立可用于物理的静止状态，再把自碰撞约束加入运动求解。
- 手部先解决静止和弯曲时的指掌几何问题，再验证接触限位或精确抓握。
- 最后复跑完整动作、压力动作、实际缓存、亚帧与视觉矩阵。

## 最后一页：真正值得复用的工作习惯

- 每次修改都知道自己在修哪一种失败，而不是凭感觉继续堆参数。
- 每项通过结论都附带对象、区域、动作、帧和采样范围。
- 能保存失败版本，也能明确拒绝它。
- 源模型、计算数组、保存缓存、渲染结果和导出结果，分别验证。
- 看数值，也看图；看关键姿势，也看帧间；看对象之间，也看对象内部。
- 发现验收范围漏洞后，扩大检查并更正结论，不把漏洞解释成成功。
- 不为了满足“完整通过”的措辞而删掉困难条件。

**可复现、可解释、可回退且不过度承诺，比一个未经证实的“已完成”更有价值。**
