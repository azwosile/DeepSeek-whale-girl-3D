## 1. 一句话结论

**生成只是开始，七成的工作量在装配、绑定和物理上。** 做得好的关键：
- **先保护对的东西**：脸、比例、UV、已验收的位置。
- **每一步都另存版本**，并且用图和数字证明“改好了、别的没坏”。
- **找到问题的根因再动手**，不要堆参数。

## 2. 全流程总览

```text
  ① 立绘（用户提供，唯一准确参考）
        │  GPT Images 2.5 Sunburst 图生图
        ▼
  ② 拆图：素体 4 视图 ＋ 服装 4 视图 ＋ 配件合集
        │  裁成单视图，交给 Tripo 多视图生成
        ▼
  ③ Tripo 3D 部件（FBX）── 先原样渲染，与输入图对比打分
        │
        ▼                                  ┐
  ④ 装配贴合 f001…f00N（Blender）           │
  ⑤ 绑定 + 姿势测试 r00N                   │  这几步在 Blender 里完成，
  ⑥ 跑步动作（动捕或程序化）               │  不属于生成插件的功能
  ⑦ 物理：裙子布料 + 头发/尾巴骨链 p00N    │
  ⑧ 卡通渲染 + 描边 t00N                   │
  ⑨ 导出回读 · 验收图 · 说明文档           ┘
```

| 阶段 | 大约占用的精力 | 最容易出的问题 |
|---|---|---|
| 拆图 + Tripo | 15% | 视图不对齐、白色衣物被抠掉、贴图烤进了高光、触发安全审核 |
| 装配贴合 | 30% | 整体错位、穿模、袖子太长、饰品位置不对 |
| 绑定 + 动作 | 15% | 自动权重大片失败、网格只跟随一部分、手臂扫进身体 |
| 物理 | 30% | 布料爆炸或穿腿；头发折叠或高频抖动；尾巴被裙子推着抖 |
| 渲染 + 交付 | 10% | 描边太细或破洞、贴图丢失（品红色）、导出贴图全黑 |

## 3. 三个工程的回顾

### 3.1 OC 第五版（学院制服）
- **起点**：现成的 Tripo 素体 + 服装包，服装包是把衬衫、背心、裙子、内衬腿、鞋都放在同一个网格里的陈列件。
- **装配**：拆成真实部件；不重复叠穿内衬腿；用可撤销遮罩处理衬衫和背心的层叠；裙腰按周向重新贴合。
- **绑定与渲染（v016–v018）**：49 骨骼的 FK 骨架，181 帧关节测试动作。试了两种卡通方向：日番硬阴影 v017 和插画式 Toon v018，**用户选了插画式**。期间试用了 Paper朱插件的描边修复和高光函数。
- **上一轮 AI 的物理工作**：做了大量避碰和修形，最后发现初始网格就有自交、亚帧也有碰撞，**没能签署完整物理验收**。这个教训写进了通用手册。
- **本轮的后续**：跑步动作（CMU 35_17）→ 手臂太短，按 MIHOYO 比例修正（v102）→ 裙子改为低模代理布料（v101/v104）。
- **最大收获**：手臂偏短的真实原因是“遮罩顶点组被算进了权重归一化”，网格只跟随了一部分骨骼，而不是骨骼长度不够。

### 3.2 大肥鱼第一版
- **起点**：素体、服装、配件三个模型。配件拼板有 50 个零件，其中 13 个和服装上已有的部件重复，**不叠加**。
- **头发整理**：拉普拉斯平滑看起来指标变好，实际把薄发片压塌、出现透缝，**否决**。改用“参考剪影约束 + 只做水平回拉 + 位移上限 3 cm”，结果存成可调强度的形态键。
- **物理三代演进**（最值得记住的经验，详见 4.7）：
  - g004：后发跑起来一折一折，用户不满意。
  - g006：不折了，但头发和鱼尾高频抖动，用户说“抖得太激烈”。
  - g007：改成带阻尼的角弹簧，加重力预载，尾巴随裙子平滑让位，问题解决。
- **用户最终的评价**：脸的风格不像，后发太乱，裙子太长，腰粗，臀大。于是决定**从立绘重新做第二版**。

### 3.3 大肥鱼第二版（从立绘重新开始的完整流程）
- **拆图**：用 GPT Images 2.5 Sunburst 出 3 张图：素体带头发 4 视图、女仆装 4 视图（素体图作为参考一起上传）、配件合集。
- **Tripo**：3 个 FBX，原样导入后正面朝 +X，尺寸归一化到 1 个单位。
- **装配 f001–f003**：素体修复 → 服装去实心、袖子对齐手臂 → 头发推到服装外 → 高跟鞋足姿、头饰、两个蝴蝶结、鱼尾。
- **用户反馈修复 f004**：
  - 眼睛贴图跑到了眼前的发丝上：在 UV 空间重绘这部分贴图。
  - 袖子太长、手穿过袖口：袖子沿手臂上移约 9 cm。
  - 后发和鱼尾穿模：把后发按竖列外推。
- **下游重建**：上游 f004 修好以后，绑定 r002、物理 p002、卡通 t002 **全部重新生成**，没有在旧文件上打补丁。
- **展示**：作为“示例 2”放进了插件介绍视频，展示从立绘到完成版的 6 个阶段。

## 4. 分阶段经验

### 4.1 立绘拆图（GPT Images 2.5）

**为什么要拆**：Tripo 对“一个完整角色”重建，头发、裙子、饰品会粘成一团。拆开后每一部分都能单独控制、单独替换。但也**不是拆得越碎越好**：三张图就够了，额度优先花在头发和裙子上。

**出图的硬要求**（每一条都是为后面的步骤服务）：
- **正交、无透视，四个视图等高、头顶和脚底对齐**：Tripo 多视图需要严格对齐。
- **A-pose**（手臂下张约 45°，双脚分开）：腋下和腿间留出空隙，网格不粘连，方便绑定。
- **平光、无高光、无投影**：第一版的“油亮感”就是因为高光被烤进了贴图，卡通着色时去不掉。
- **浅灰背景 #C8C8C8，不用白底**：白色荷叶边和围裙在白底上会被当成背景抠掉。
- **闭嘴中性表情**：张开的嘴会被做成几何体。
- **4 视图用 16:9 横排一行，不要 2×2**：2×2 排列时人物会小一半。

**两个实用技巧**：
- 服装图要把**已经生成好的素体图作为参考**一起上传，比例和姿势才能完全一致，贴合时省很多事。
- 不满意时在**同一个对话里追加“只改一处”的指令**（Sunburst 擅长这种编辑），不要重新生成。

**安全审核**：描述身体的词（紧身、人台、胸、裆、赤脚等）组合在一起容易被拦截。改成“游戏设定图的白色基础服装”，体型只用中性描述。

### 4.2 Tripo 生成

- 交给 Tripo 之前，把 4 视图裁成 4 张**等高、居中、留白**的单图，文件名标 front / left / back / right。
- **拿到模型先原样渲染**，和输入图做剪影对比，再出一张评估图给用户看。不要拿到就直接开始装配。
- **朝向要实测**：这次的 FBX 正面朝 +X，而不是 Blender 习惯的 −Y。判断方法是看包围盒，再从两个方向各渲染一张。
- Tripo 的法线方向不可靠，脸部还常有双层壳。后面判断“点在模型内还是外”时，要用射线穿过面数的**奇偶**来判断，不要看法线。
- 贴图可能串色：大肥鱼第二版眼睛的颜色被烤到了眼前的发丝上，要在装配阶段修。

### 4.3 装配贴合

**核心原则：以素体为尺度基准，先整体后局部，先内层后外层。**

1. **整体对齐**：用肩、腰、胯、膝等地标求一个整体的缩放和平移（可逆、可记录）。
2. **服装去实心**：Tripo 的服装常常是实心的，内部有封口面，要挖空才能套到身上。
3. **局部贴合**：袖子对齐手臂轴，裙腰对齐腰线。
4. **消穿模**：内层（皮肤）往里收，外层（头发）往外推，位移沿发束平滑传播，并设上限。
5. **配件逐件装**：高跟鞋要把脚摆成踮起的足姿并整体抬高（这次抬高了 2.6 cm），删掉素体自带的鞋；头饰按头宽缩放；鱼尾搜索最佳附着点和角度。

**几条教训**：
- **用户说“整体错位”，一定要四视图逐个对照**。错的那一版保留，并标注“已作废”。
- **已经验收的位置要锁定**：大肥鱼第一版里，头发表面变了以后，优化器建议把头饰前移 5 cm，这会遮住鱼鳍，最后锁回已验收的值。
- **找最小的上游原因**：袖子太长就缩袖子，不去改手；头发压进鱼尾就外推头发，不去改鱼尾。
- **头发不能用通用平滑**（会压塌薄片），要用参考剪影来约束。
- **改体型时，身体和衣服用同一个映射**，两者的间距才能保持（腰收细 8%，臀不变）。

### 4.4 绑定与姿势测试

- **自动权重只在“只含皮肤”的副本上算**，再传回原网格。直接算整个多片区网格，实测有 1.8 万个顶点的权重是 0。
- **权重归一化只算变形骨**。把遮罩组也算进去，网格只会跟随一部分骨骼（OC5 的手腕因此跑到了手掌外面）。
- 袖子要单独处理权重（先剥掉躯干骨的影响），裙子交给布料。
- **先做姿势测试，再做物理**：f20 转头、f40 抬臂、f60 屈肘、f80 屈膝，每个姿势都看正面和侧面图。
- 手臂比例参照外部模型时，用“**肩高**”做基准再比较。Q 版或大头的 OC 用全身高做基准会失真。

### 4.5 跑步动作

- **动捕**：CMU 35 号受试者的 run/jog。截取一个周期循环使用，先做原地跑；腿部幅度约 85%，**手臂外展 10°**，长手臂才不会扫进胸口和裙子。用了 CMU 数据就**必须署名**。
- **程序化**：大肥鱼第二版用的是 16 帧一周期的关键帧慢跑，循环无缝，不需要署名。
- 检查：循环首尾差为 0，脚底不穿地（约 3 mm），滑步要写明。

### 4.6 裙子布料

**不要直接对高模裙子开布料模拟**：会爆炸，会穿腿。验证过的做法：
1. 做一个**低模锥形代理**（约 48 段 × 13–16 环），腰部几圈渐变钉固在髋骨上。
2. 给大腿、小腿、前臂、手加**胶囊碰撞体**；大腿上部截掉一段，避免和钉固区冲突。
3. **预滚**：先静止 30 帧，再用 20 帧淡入跑步；模拟 3 圈，**取已经稳定的第 3 圈**，首尾交叉淡化，使循环无缝。
4. 烘焙代理，再用 **Surface Deform** 让高模裙子跟随代理。
5. 看指标：最大拉伸（1.1–1.4 之间可以接受）、腿和裙子的相交统计。

**试过但失败的做法**：只加步数或刚度；给鱼尾加碰撞让布料绕开（拉伸 2.7）；用几何方法压裙子（拉伸 4–5）；用全身射线修裙摆（射线命中低垂的手，把裙摆推歪）。

### 4.7 头发与尾巴物理（最重要的一课）

头发和尾巴用**骨链 + 自己写的解算器预烘焙**：可控、可以导出到引擎，不会甩飞。演进过程如下：

| 版本 | 做法 | 用户看到的问题 | 真正的原因 |
|---|---|---|---|
| g004 | 只约束长度，每个点各自限幅 | 后发“一折一折” | 没有抗弯，限幅和碰撞把发束挤成了手风琴 |
| g006 | 每次迭代把关节**硬拉回**原来的弯曲 | 头发和鱼尾抖得太激烈 | 逐迭代硬改位置等于往系统里注入能量，产生 9–11 Hz 颤振 |
| **g007** | **带阻尼的角弹簧** + 重力预载 + 角度上限只作安全约束 + 碰撞放在最后 | 平顺，不折，不穿 | 弹簧以“力”的形式进入积分，不会注入能量 |

几个关键细节：
- **阻尼比 1.5** 最好（1.0 和 2.0 都试过）。
- **重力预载**：弹簧变软以后，站立时头发会下垂 3 cm。可以预先修正目标形状，让头发在重力下稳定后正好回到建模形状。
- **尾巴不要每帧接收裙子的推力**。应该把裙子鼓起的平均程度平滑处理，变成尾巴整体绕根部的外摆，这样就没有高频抖动。
- **不要用后期滤波去“磨平”抖动**：试过，头发会变卷。

**怎么判断“抖不抖、折不折”**：用技能里的 `motion_metrics.py` 看几个数（实测参考值）：
- 梢点加速度 p95：平滑时约 13–32，颤振时 150–310。
- 高于 5 Hz 的能量占比：正常 ≤ 0.08，颤振时 0.44–0.96。
- 弦长比（根到梢的直线距离 ÷ 静止时的距离）：≥ 0.95 正常，远小于 1 说明被折叠了。

### 4.8 卡通渲染与描边

- **先让用户选风格**：同姿势、同机位、同灯光下出两种方向（硬阴影 / 插画式）。这位用户选了**插画式 Toon + 描边**。
- **插画式 Toon 的配方**（EEVEE 原生节点）：自发光为主的三层色阶，冷色阴影，皮肤用暖色阴影，脸部单独控制阴影，头发加受控高光。移植到新角色时，**灯光要按新角色的朝向转过去**。
- **描边**：反转外壳（Solidify 翻转法线），厚度按对象设定：身体约 0.0024、衣服约 0.003、饰品约 0.0022。0.0011–0.0014 太细，看不出来。
- **Paper朱二次元渲染助手**：可以作为描边和高光的参考实现，详见第 7 节。注意它默认的高光在深色衣服上会形成亮斑，要调低。
- **改材质要证明没动别的**：用 `mesh_audit.py` 对比前后，拓扑、UV、坐标的哈希必须一致。
- 卡通着色只在 Blender 里有效，导出到游戏引擎要另做材质。

### 4.9 导出与交付

- 编辑工程和导出文件分开；导出后**重新导入检查**：对象数、骨骼数、高度、帧范围（FBX 常有 1 帧偏移）、贴图有没有变黑。
- 每一轮都写一份说明：改了什么、为什么、数字对比、什么没变、文件在哪里、还剩什么问题。
- 物理没有完全验收，就要在标题里写“预览版”。**可复现、可解释、可回退，比一句没有证据的“已完成”更有价值。**

## 5. 怎样和 AI 协作（给使用者）

1. **指定唯一准确的参考图**。其他图要说明是“辅助”。
2. **把不满意的地方一条条列出来**，AI 会写进任务卡，每一轮都复述。
3. **要求每轮都给四视图加特写的前后对比图**，并且同机位、同帧。
4. **要求说明“没改什么”**：哈希对比，或者重新打开后的验证结果。
5. 看到“已完成”时，问一句：**验收范围到哪里**？覆盖了哪些动作、哪些帧，有没有检查自碰撞和亚帧？
6. 需要花额度的步骤（Tripo、图像生成）可以提前定规则，例如“配件图整张导入，不裁剪”。
7. 反馈越具体越好：“跑步时后发一折一折”比“头发不好看”更容易定位到根因。

## 6. 上一轮经验与本轮补充的对照

| 主题 | 上一轮 AI 的结论（通用手册） | 本轮新增或验证的内容 |
|---|---|---|
| 装配 | 最小上游原因；不要把修复变成重新设计 | 补齐了从立绘开始的完整链路（拆图提示词、Tripo 评估）；用奇偶规则做内外判断；UV 重绘修贴图串色 |
| 头发 | 不要用全局高度阈值；发根过渡区要单独诊断 | 薄发片禁止通用平滑；参考剪影约束；骨链物理三代演进与指标 |
| 绑定 | 优先复用骨架；先做姿势测试 | 自动权重只在皮肤副本上算；只按变形骨归一化（手臂偏短的根因） |
| 布料 | 先修初始状态；代理稳定 ≠ 高模安全 | 一套可以复用的代理布料流程（预滚、取稳定周期、交叉淡化循环） |
| 物理验收 | 自碰撞、亚帧、缓存要独立检查；时空一起求解 | 颤振的根因（逐迭代位置投影注入能量）和解法（阻尼角弹簧）；用 HF 能量占比和加速度 p95 量化“抖” |
| 渲染 | 先锁定风格；Shader to RGB 不能迁移到引擎 | 插画 Toon 移植到新角色（灯组随朝向旋转）；描边厚度的经验值 |
| 自动化 | 不要猜终端；长任务启动和查询分离；不泄露凭据 | 多个 EEVEE 进程并行会丢贴图；渲染路径必须用绝对路径；二进制分块传输加哈希校验 |
| 共同点 | **阈值是合同；有限范围通过要讲清范围；失败的版本也是资产** | 同意，并在每轮 README 中执行 |

## 9. 术语小词典

| 词 | 意思 |
|---|---|
| 4 视图 | 正、左、背、右四个方向的全身图 |
| A-pose | 手臂斜向下张开约 45° 的站姿（T-pose 是水平张开） |
| 连通片区 | 网格中互相连着的一块；常用来分开头发、衣服、饰品 |
| 剪影 IoU | 模型渲染的轮廓和参考图轮廓的重合比例，1 表示完全重合 |
| 穿模 | 一个物体的表面跑进了另一个物体里 |
| 权重 / 归一化 | 每个顶点跟随各骨骼的比例；归一化就是让这些比例加起来等于 1 |
| 变形骨 | 真正带动网格的骨骼（控制骨、辅助骨不算） |
| 代理（布料代理） | 用来做模拟的简化网格，高模再跟着它动 |
| Surface Deform | 让一个网格贴着另一个网格变形的修改器 |
| 预滚 | 正式动作开始前先让布料模拟一段时间，进入稳定状态 |
| 骨链 / Verlet | 头发、尾巴用一串骨骼表示；Verlet 是一种简单稳定的物理积分方法 |
| 角弹簧 / 阻尼比 | 让关节回到原来角度的“弹力”；阻尼比决定回弹时晃几下（约 1 为刚好不晃，1.5 偏稳） |
| 重力预载 | 预先修正头发的目标形状，抵消重力造成的下垂 |
| HF 能量占比 | 运动中高于 5 Hz（很快的抖动）的那部分能量所占的比例 |
| 弦长比 | 发束从根到梢的直线距离和静止时的比值，变小说明被折叠了 |
| 亚帧 | 两个整数帧之间的时刻；整数帧不穿模，不代表中间不穿 |
| 反转外壳描边 | 把模型复制一层、稍微放大、翻转法线，只显示背面，形成描边 |
| Shader to RGB | Blender EEVEE 的节点，把光照结果转成颜色再分层，用来做卡通着色 |
| 哈希 | 数据的“指纹”，两次一样就说明数据没变 |
| 回读 | 把导出的文件重新导入，检查内容是否正确 |
