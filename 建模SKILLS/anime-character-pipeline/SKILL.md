# 二次元角色全流程（立绘 → Tripo → Blender → 可动卡通成品）

本技能来自三个实际做完的角色工程，经验已经过实践检验。**数字都是“当时那个角色的实测值”，不是通用参数**，换角色要重新量。

## 0. 开工前必须做的 5 件事

1. **建任务卡**（若有 ShunCode/MCP 任务卡工具）：每次对话先建或更新，同时只能有一个 in_progress；结束前发终态快照。
2. **实测工具，不按文档猜**：先列出真实可用的工具，确认 Blender 路径与版本（实测 5.2.2 LTS）以及终端类型（Windows 主机上的桥接终端也可能是 Bash）。文档写了 `blender_*` 工具，不代表当前连接已经注册。
3. **读参考优先级**：用户指定的“唯一准确参考图”排第一，其次是同角色的多视图，再次是外部参考模型（只量比例，不复制几何）。按第 3 节逐条写下用户的明确偏好。
4. **定交付等级与验收范围**：分清静态展示、Blender 动画、引擎资产三种目标。“有限范围通过”必须写明对象、区域、动作、帧范围和采样方式。
5. **不覆盖**：每一步都另存新版本（f/r/p/t 编号，见第 4 节）。源 FBX、原图和用户场景只读。

## 1. 主流程与每关的门槛

| 阶段 | 产出 | 通过门槛（全部满足才进入下一关） | 详见 |
|---|---|---|---|
| A 立绘拆图 | 素体 4 视图、服装 4 视图、配件合集各 1 张 | 正交、等高、A-pose、平光、灰底 #C8C8C8、闭嘴中性表情；裁成单视图 | references/02 |
| B Tripo 生成 | 每组一个 FBX | 原样导入后做多视图渲染，与输入图对比（剪影 IoU 和目视都要看）；记录朝向和尺度 | references/02 |
| C 装配贴合 f | `*_assembly_fNNN.blend` | 以素体为尺度基准；正、侧、背、斜四视图加特写与参考图叠图；穿模清单中的问题有量化、有归因 | references/03 |
| D 绑定 r | `*_rig_rNNN.blend` | 无未赋权皮肤；只按变形骨归一化；姿势测试 f20 转头、f40 抬臂、f60 屈肘、f80 屈膝全部过目 | references/04 |
| E 动作 | 循环动作 | 首尾差为 0；脚底不穿地；手臂不扫进胸口和裙子 | references/04 |
| F 物理 p | 布料缓存 + 骨链烘焙 | 不爆、不折、不抖：拉伸、弦长比、>5 Hz 能量占比、加速度 p95 都过线；对象间穿插有统计 | references/05 |
| G 卡通渲染 t | `*_toon_tNNN.blend` | 网格、UV、权重、动作的哈希不变（`scripts/mesh_audit.py`）；正面、背面、特写都看过 | references/06 |
| H 导出/交付 | GLB/FBX + 说明 | 干净进程回读；贴图不黑；README 写清“已验证 / 未验证 / 限制” | references/08 |

每关都要**渲染图并亲眼看过**。“文件已保存”“函数返回成功”都不算通过。

## 2. 十条硬规则（踩过的坑）

1. **先保护正确的，再修错误的。** 脸、已确认的比例、UV、材质、已验收的饰品位置都要锁定。优化器建议移动已验收的饰品时，以用户验收过的值为准（大肥鱼 v1 的头饰锁回 v5 的值）。
2. **最小上游原因。** 袖子太长就缩袖子，不去改手；头发盖住鱼尾的穿模，把后发外推，不去改鱼尾设计。
3. **薄条带不能用拉普拉斯平滑。** 头发是折叠薄片，平滑会把它压塌、出现透缝。整理头发用“参考剪影约束 + 只做水平回拉 + 沿发束扩散 + 位移上限”。
4. **自动权重只在“只含皮肤”的副本上算**，再传回原网格。多片区网格直接算 ARMATURE_AUTO，会有上万个零权重顶点。
5. **权重归一化只算变形骨。** 遮罩组、非变形组参与归一化，会让网格只跟随一部分（OC5 手臂少跟了 40%）。
6. **骨链物理不能用“逐迭代把位置硬拉回”来做弯曲记忆**：这样会注入能量，产生 9–11 Hz 颤振。应改用带阻尼的角弹簧（以力的形式进入积分），加重力预载，角度上限只作为安全约束，碰撞放在最后一步。
7. **布料先修初始状态，再调参数。** 初始穿透、固定端、尺度出问题时，加步数、加刚度都没用。做法是低模代理布料 + 预滚 + 取稳定周期 + Surface Deform 带动高模。
8. **对象间零交叉 ≠ 自碰撞通过 ≠ 亚帧通过 ≠ 最终缓存通过。** 每项单独检查，单独报告。
9. **阈值是合同。** 失败后不能放宽阈值、裁掉难测区域或只挑好帧。
10. **单变量对比。** 风格和材质试验只改材质与灯光，然后用哈希证明几何、UV、权重、骨架、动作没变。

## 3. 用户偏好记录（本工作区用户明确说过的，换角色时也先问同类问题）

- 只有“唯一准确参考图”是准的，其他图仅供补充。用户对“整体错位”很敏感：**每轮必须四视图核对**，要求严谨、细致、深度思考。
- 上一版里被用户拒绝过的：后发杂乱、头发下端太卷、跑步时后发一折一折、鱼尾和头发抖得太激烈、女仆裙太长、腰太粗、臀太大、脸风格不像。
- 裙子用**布料模拟**（不用骨骼跟随）；渲染选**卡通 / 赛璐璐 + 描边**（插画式 Toon，三层色阶）。
- 手臂比例参照参考图和 MIHOYO 模型，**只量取数值**。MIHOYO 模型的规则是允许改造，禁止二次配布和商用。
- 拆图：3 张（素体带头发、女仆装、配件合集），素体和服装要 4 视图，用 GPT Images 2.5 **Sunburst** 做图生图。**不要去掉服装袖子**（Tripo 会处理）；**配件图不裁剪**，整张导入以节省额度。
- 视频展示要“从素体到完成版”全过程，用 HTML+CSS 制作。
- 随机数类小任务直接输出，不调用工具，也不写解释。

## 4. 版本与目录约定

```
<角色>/原图/            用户原图（只读）
<角色>/生成参考图/      GPT 拆图结果与 4 视图裁切
<角色>/生成模型/<组>/   Tripo 原始 FBX（只读）
<角色>/装配/            *_body_fNNN / *_assembly_fNNN / *_rig_rNNN / *_phys_pNNN / *_toon_tNNN .blend
                        + 同名 *_report.json + 中文验收图「阶段_版本_内容.jpg」+ 生成脚本 .py
```
- f＝装配修复，r＝绑定，p＝物理，t＝卡通。修一个上游版本（如 f004）后，必须把下游 r/p/t 全部重建一遍（r002/p002/t002），不能只补丁下游。
- 被否决的版本保留并在文件名或 README 中标注“已否决 / 已作废”，不删除。
- 每轮写一份 README：状态（是否签署完整验收）、做法、数字、文件、残留问题、数据署名。

## 5. 执行方式（MCP / 后台 Blender）

- Blender 一律用后台进程：`blender.exe -b [file.blend] --factory-startup --python-exit-code 1 -P script.py -- 参数`。
- 长任务：短超时启动，再轮询输出。结果未知时**不要重跑写入脚本**，先查日志、报告和文件哈希。
- 并行渲染 ≤ 3 个；**同一工程不要同时开两个 EEVEE 进程**，否则贴图会丢失，显示成品红色。
- 更多环境坑（相机朝向、numpy 2、BVH 返回值、二进制传输、会话过期）见 references/09。

## 6. 工具脚本（scripts/，已在 Blender 5.2.2 上实测）

| 脚本 | 用途 |
|---|---|
| `mesh_audit.py` + `compare_audit.py` | 结构审计（片区、边界边、非流形边、零面积面）和保护哈希（拓扑、UV、坐标、权重、材质）；对比两个版本，证明“只改了该改的”。 |
| `multiview_render.py` | 自动取景，正交渲染正、左、背、右视图加特写；可直接 `--import` Tripo FBX；`--front` 指定正面朝向；`--frame` 逐帧推进以保证缓存正确。 |
| `motion_metrics.py` | 骨链质量：梢点加速度 p95、>5 Hz 能量占比、速度反转率、弦长比、关节弯曲 p95。判断“抖不抖、折不折”。 |

## 8. 交付报告必须回答的六个问题

1. 这轮改了什么？为什么改（对应哪条用户意见或哪项失败）？
2. 用什么方法改的？有没有被否决的路线？
3. 数字前后对比如何？
4. 哪些东西被证明没变（哈希、回读）？
5. 文件在哪里（完整路径）？哪个是最终文件？
6. 还剩什么问题？验收范围到哪里为止？
