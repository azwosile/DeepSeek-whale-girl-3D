# 01 交付合同与输入审计

## 1.1 开工前问清楚
- 目标：静态展示 / Blender 内动画 / 游戏引擎资产 / 可编辑制作源？
- 唯一准确的参考图是哪张？其他图（AI 拆图、旧版模型）只算辅助。
- 用户明确不满意的点（逐条写进任务卡，每轮复述）。
- 不可变清单：脸、表情、已确认的比例、UV、原贴图、已验收的饰品位置、源 FBX。
- 可变清单：本轮允许动的对象和区域、位移上限（例如“稍微平整”＝单顶点 ≤ 3 cm）。
- 交付等级：预览版（未签署完整物理验收）还是成品？标题和首段要写明。

## 1.2 输入资产清单（每个 FBX 都做）
用 `scripts/mesh_audit.py` 导出结构报告，再用 `scripts/multiview_render.py --import` 渲染四视图。

记录这些内容：
- 顶点 / 面 / 连通片区 / 边界边 / 非流形边 / 零面积面。
  - **注意**：衣服开口、发片、UV 接缝都会产生边界边，这些数字不能全当成破洞，也不能靠全局焊接或重网格化来消除。
- 是否有骨架、权重、形态键；贴图分辨率与路径。
- 一个对象里装了多少个“陈列件”：Tripo 的服装包常把衬衫、背心、裙子、内衬腿、鞋和小饰件放在同一网格里。
- 重复件：配件图里与服装上已有部件重复的高细节件，按“**不叠加**”处理，最多选择性替换。
  - 实例：大肥鱼 v1 的配件拼板有 50 件，其中 13 件和服装重复。

## 1.3 参考图优先级与量法
- 插画会把头画大、小腿画短：**不要在原图上量绝对高度**，用解剖位置描述（“到膝盖”“高腰线”“手腕约在胯部”）。
- 俯拍参考存在透视缩短，手臂长度要用“下垂时手腕约在胯部、指尖到裙中段”这类关系来定。
- 外部参考模型（如 MIHOYO）用**稳定基准归一化**再比较。
  - 大头短腿的 Q 版或 OC，不要用全身高做基准，改用“肩关节离地高度 Sh”。
  - 实测（6 个星铁角色）：上臂 0.171–0.179 Sh，前臂 0.148–0.167 Sh，手 0.123–0.127 Sh，全臂 0.447–0.469 Sh。
- 单张图不能确定深度：没有背面参考时，要区分“设计有证据”和“为完成模型所作的假设”，并在报告里写明。

## 1.4 坐标约定（统一后再干活）
- 单位米，Z 向上，脚底 z = 0。在报告第一行写明正面方向和“角色左侧”的方向。
  - 大肥鱼第二版约定：正面 +X，角色左侧 +Y，身高 1.62 m，7 头身。
- 粗对齐优先用**可逆的整体相似变换**（缩放 s、平移 tx/tz），参数写进 JSON（例：s = 0.9156，tx = 0.0978，tz = 0.9206）。
- 验收不能只看包围盒：要用参考图叠图，看肩、腰、胯、膝、踝等地标的高度差。
